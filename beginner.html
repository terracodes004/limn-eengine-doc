Creating a Display and calling start()

To initialize your game, create an instance of the Display class and run start(). This sets up your game window canvas size and hooks it into the game loop.

See more... 
<script src="epic.js"></script>
<script>
const display = new Display();
display.start(800, 600); // Width, Height

const player = new Component(50, 50, "red", 400, 300, "rect");
display.add(player);

function update() {
    // Game loop logic runs here automatically
}
</script>

✅ What happens: start() builds your canvas, attaches it to the DOM, and prepares the core loop. Note that your engine instance must be named exactly display.

Class / Method Purpose Parameters
Display() Core engine framework instance. Manages input arrays, camera systems, and loop ticking. None
display.start() Creates and inserts the canvas to begin the update cycle loop. width, height, elementNode (optional)

Adding and moving Component objects

A Component is your standard engine actor node: players, obstacles, collectibles, or projectiles.

Moving your Components

To move your Components you just have to change the X and Y position. 

player.x = 10
player.y = 10
For continuous motion you just have to change the speed 
player.speedX = 1
player.speedY = 1
No need for player.x += 1, Limn Engine has you covered.

Class Purpose Parameters

Keyboard input (display.keys) and delta‑time movement

Capture global hardware keyboard actions via the tracked key array matrix display.keys.

See more...

To keep movement smooth and uniform across variable monitor frame rates, multiply your speed by display.deltaTime inside the update() loop:

The display.keys array stores which keys are currently pressed. Each key has a numeric keycode. Use it inside update() to change the player’s speedX and speedY.

Common keycodes: left=37, right=39, up=38, down=40, space=32, A=65, D=68, W=87, S=83.

function update() {
    player.stopMove(); // Clear automatic speeds before applying input
    
    let speed = 200 * display.deltaTime; // 200 pixels per second

    if (display.keys[37] || display.keys[65]) { player.x -= speed; } // Left / A
    if (display.keys[39] || display.keys[68]) { player.x += speed; } // Right / D
    if (display.keys[38] || display.keys[87]) { player.y -= speed; } // Up / W
    if (display.keys[40] || display.keys[83]) { player.y += speed; } // Down / S
}

Screen boundaries with move.bound()

Prevent players or game elements from shifting out of view beyond the active layout canvas borders.

See more...

Pass your actor node into move.bound() inside your main runtime update execution loop:

function update() {
    // Handle player control tracking...
    
    // Clamp coordinates safely inside game board dimensions
    move.bound(player);
}

If you need custom boundaries instead of the total canvas size, you can specify constraints using move.boundTo(component, left, right, top, bottom).

Rectangle collision (crashWith())

Detect when two elements touch or collide using Axis-Aligned Bounding Box intersecting structures.

See more...

The method returns a true boolean conditional check whenever bounds overlap:

function update() {
    if (player.crashWith(enemy)) {
        console.log("Collision detected!");
        player.setColor("blue"); // Change look state
    }
}

Images with setImage()

To use an image, create a component with type "image" and the color will be the image path. You change the image using setImage().

See more... 
const character = new Component(64, 64, "hero.png", 100, 100, "image");
display.add(character);

// Convert standard block node into an active sprite asset map
character.setImage("img/hero.png");

You can change the image later (e.g., power‑up) with player.setImage("player_powered.png"). To switch back to a coloured rectangle, use player.setColor("blue").

Images are not automatically resized – set the component’s width and height to match your sprite dimensions.

💡 Fallback Behavior: If the specified image asset fails to load or cannot be found, the canvas gracefully displays the base color block layout instead.

Sound with Sound class

Incorporate audio background loops and sound effects cleanly into game triggers.

Load a sound using the Sound class, then call .play(). Supported formats: .wav, .mp3, .ogg.

const zapSound = new Sound("audio/zap.mp3");
const backgroundTrack = new Sound("audio/music.mp3");

backgroundTrack.play(); // Play loop track safely

function update() {

    }
}

Game states using display.scene

Isolate distinct parts of your game like start screens, main gameplay sections, and game over maps.

See more...

Use display.scene to group components. Each component can be assigned to a scene number. Only components whose scene matches the current display.scene are rendered.

Components added using display.add(item, sceneId) will only update and render if the value matches the current display.scene tracking state:

const titleText = new Component(300, 40, "white", 100, 100, "text");
const avatar = new Component(40, 40, "green", 200, 200, "rect");

display.add(titleText, 0); // Active in Scene 0 (Menu)
display.add(avatar, 1);    // Active in Scene 1 (Gameplay)

function update() {
    if (display.scene === 0) {
        if (display.keys[13]) { display.scene = 1; } // Press Enter to play
    } else if (display.scene === 1) {
        // Run core simulation ticks smoothly away from menu interfaces
    }
}
