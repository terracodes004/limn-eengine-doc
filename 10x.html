Dual-Canvas with perform()

Call display.perform() before display.start() to activate Limn's dual-canvas pipeline — the single biggest performance upgrade available.

see more... 
const display = new Display();

// MUST come before start()
display.perform();

display.start(800, 600);
display.backgroundColor("#111");

// Static objects go on the fake (offscreen) canvas
const bg = new Component(800, 600, "#222", 0, 0, "rect");
fake.add(bg);  // ← fake canvas, not display

// Dynamic objects go on the main display as usual
const player = new Component(40, 40, "blue", 400, 300, "rect");
display.add(player);

function update() {
    if (display.keys[39]) player.speedX =  4;
    if (display.keys[37]) player.speedX = -4;
    else player.speedX = 0;
}

✅ The fake canvas is drawn once (or when explicitly refreshed) and composited onto the main canvas each frame. Static objects cost almost zero render time. Dynamic objects render normally on top.

NOTE: perform() must be called before start(). Calling it after has no effect.

MethodPurpose
display.perform()Activate dual-canvas pipeline
fake.add(obj)Add a static object to the offscreen canvas

The fake Canvas Explained

fake is a second Display instance created by perform(). It has its own canvas, camera, tile system, and component list — but it renders offscreen and gets pasted onto the main canvas each frame.

see more... 
// fake is a full Display — you can use all the same APIs
fake.tile = [
    new Component(64, 64, "green",  0, 0),
    new Component(64, 64, "#555",   0, 0),
];
fake.map = [
    [1,1,2,1,1],
    [2,1,1,2,1],
];
fake.tileMap();
fake.tileFace.show(); // draws into the offscreen buffer

// You can also add regular components
const stars = new Component(800, 600, "#000011", 0, 0, "rect");
fake.add(stars);

// The main canvas gets the fake canvas drawn on it every frame
// Main canvas then draws dynamic objects on top

✅ Think of fake as the background layer. Anything that doesn't move or rarely changes belongs on fake. Anything that moves every frame (player, enemies, bullets, particles) goes on display.

Syncing fake & display cameras

In perform mode both canvases have separate cameras. You must sync them manually so the background stays aligned with the foreground when scrolling.

see more... 
function update() {
    // Main camera follows player
    display.camera.follow(player, true);

    // Sync fake camera to match
    fake.camera.x = display.camera.x;
    fake.camera.y = display.camera.y;

    // If shaking, shake both
    if (hit) {
        display.camera.shake(8, 6);
        fake.camera.shake(-8, -6); // opposite for realism
    }
}

✅ Without syncing, the foreground (player, enemies) moves with the camera but the background (tiles, stars) stays frozen at the origin — a very obvious bug. Always sync both cameras in update().

NOTE: Sync fake.camera after you call display.camera.follow() so you copy the already-updated values.

deltaTime-based Movement

Use display.deltaTime to make movement frame-rate independent. Your game runs at the same speed on 30fps and 60fps machines.

see more... 
// Limn passes deltaTime to update()
function update(dt) {
    const SPEED = 250; // pixels per second (not per frame)

    if (display.keys[39]) player.speedX =  SPEED * dt;
    else if (display.keys[37]) player.speedX = -SPEED * dt;
    else player.speedX = 0;

    if (display.keys[40]) player.speedY =  SPEED * dt;
    else if (display.keys[38]) player.speedY = -SPEED * dt;
    else player.speedY = 0;
}

// Without deltaTime (frame-dependent — bad on slow machines):
// player.speedX = 4; // moves 4px/frame = 240px/sec at 60fps BUT 120px/sec at 30fps

// With deltaTime (frame-independent — always 250px/sec):
// player.speedX = 250 * dt;

✅ dt is approximately 1/fps. At 60fps dt ≈ 0.0167. Speed × dt gives you pixels per second regardless of frame rate. Always define speeds in pixels-per-second when using deltaTime.

PropertyValue at 60fpsValue at 30fps
display.deltaTime~0.0167~0.033
250 * dt~4.17 px/frame~8.33 px/frame
Result250 px/sec ✅250 px/sec ✅

clearMargin Optimisation

display.clearMargin tells the engine how large an area to clear each frame. Setting it correctly avoids clearing unnecessary canvas space.

see more... 
const display = new Display();
display.start(800, 600);

// Default: clears width² × height² (very large — safe but slow for huge worlds)
// For a standard game, the canvas size is enough:
display.clearMargin = [800, 600]; // [width, height]

// For scrolling worlds larger than the canvas:
display.clearMargin = [2000, 2000]; // match your world size

// The engine uses this inside clear():
// ctx.clearRect(0, 0, clearMargin[0], clearMargin[1])

✅ The default is [width², height²] which is intentionally large to handle zoomed/rotated canvases. For most games you can set it to the canvas size or world size to improve performance.

ValueUse case
[800, 600]Fixed-camera game, no zoom
[worldW, worldH]Scrolling world
[w², h²]Default — safe for any rotation/zoom

Custom Particle System from Scratch

You understand the built-in ParticleSystem — now build a specialised one. The engine is open: draw directly on the context for maximum control.

see more... 
// Custom lightweight particle pool
class TrailSystem {
    constructor() {
        this.pool = [];
    }
    emit(x, y, color) {
        this.pool.push({ x, y, color, alpha: 1, size: 6 });
    }
    update(ctx) {
        for (let i = this.pool.length - 1; i >= 0; i--) {
            const p = this.pool[i];
            p.alpha -= 0.04;
            p.size  -= 0.15;
            if (p.alpha <= 0 || p.size <= 0) {
                this.pool.splice(i, 1);
                continue;
            }
            ctx.save();
            ctx.globalAlpha = p.alpha;
            ctx.fillStyle = p.color;
            ctx.beginPath();
            ctx.arc(p.x, p.y, p.size, 0, Math.PI * 2);
            ctx.fill();
            ctx.restore();
        }
    }
}

const trail = new TrailSystem();

function update() {
    trail.emit(player.x + 20, player.y + 20, "#7fffb2");
    trail.update(display.context);
}

✅ Drawing directly with display.context inside update() gives you pixel-level control. This pattern is faster than adding hundreds of Components to the comm[] array.

Extending the Engine

Limn is open JavaScript — you can patch any class, add methods to Component, or hook into the game loop with no build tools needed.

see more... 
// Add a health system to Component
Component.prototype.setHealth = function(max) {
    this.hp    = max;
    this.maxHp = max;
};
Component.prototype.damage = function(amount) {
    this.hp = Math.max(0, this.hp - amount);
    return this.hp <= 0; // returns true if dead
};
Component.prototype.drawHealthBar = function(ctx) {
    const pct = this.hp / this.maxHp;
    ctx.fillStyle = "#333";
    ctx.fillRect(this.x, this.y - 10, this.width, 6);
    ctx.fillStyle = pct > 0.5 ? "lime" : pct > 0.25 ? "orange" : "red";
    ctx.fillRect(this.x, this.y - 10, this.width * pct, 6);
};

// Usage
player.setHealth(100);
enemy.setHealth(50);

function update() {
    if (player.crashWith(enemy)) {
        const dead = enemy.damage(10);
        if (dead) enemy.hide();
    }
    player.drawHealthBar(display.context);
    enemy.drawHealthBar(display.context);
}

✅ Prototype extension is the cleanest way to add features without modifying epic.js itself. Your extensions survive engine updates.

SoundManager

SoundManager gives you named sounds, music control, master volume, SFX volume, muting — a complete audio pipeline.

see more... 
// Create and attach globally
window.soundManager = new SoundManager();

// Load sounds by name
soundManager.load("jump",   "audio/jump.wav");
soundManager.load("hit",    "audio/hit.wav");
soundManager.load("music_bg","audio/background.mp3", { loop: true });

// Set volumes (0.0 – 1.0)
soundManager.masterVolume = 0.8;
soundManager.sfxVolume    = 1.0;
soundManager.musicVolume  = 0.5;

// Play background music
soundManager.playMusic("music_bg");

// Play SFX
function update() {
    if (display.keys[32] && player.gravitySpeed >= 0) {
        soundManager.play("jump");
        player.gravitySpeed = -10;
    }
    if (player.crashWith(enemy)) {
        soundManager.play("hit");
    }
}

// Mute toggle
window.addEventListener("keydown", e => {
    if (e.key === "m") soundManager.mute();
    if (e.key === "u") soundManager.unmute();
});

// Also available via move.sound.*
move.sound.playMusic("music_bg");
move.sound.setMasterVolume(0.5);

✅ Sounds prefixed with music_ automatically use musicVolume. Others use sfxVolume. Both are scaled by masterVolume.

MethodPurpose
soundManager.load(name,src)Preload a sound by name
soundManager.play(name)Play a sound effect
soundManager.playMusic(name)Start looping background music
soundManager.stopMusic()Stop current music
soundManager.mute() / unmute()Toggle all audio

AnimatedSprite Advanced

AnimatedSprite extends Sprite with named animation clips, one-shot animations, and frame-range control per state.

see more... 
const hero = new AnimatedSprite("hero_sheet.png", 64, 64, 200, 300);

// addAnimation(name, startFrame, endFrame, speed, loop)
hero.addAnimation("idle",   0,  3,  10, true);   // loops
hero.addAnimation("run",    4, 11,   5, true);   // loops
hero.addAnimation("jump",  12, 15,   4, false);  // plays once
hero.addAnimation("attack",16, 19,   3, false);  // plays once
hero.addAnimation("die",   20, 27,   6, false);  // plays once
display.add(hero);

let attacking = false;

function update() {
    if (display.keys[39]) {
        player.speedX = 4;
        hero.playAnimation("run");
    } else {
        player.speedX = 0;
        hero.playAnimation("idle");
    }
    if (display.keys[90] && !attacking) { // Z to attack
        hero.playAnimation("attack");
        attacking = true;
        setTimeout(() => attacking = false, 300);
    }
    // updateAnimation() drives the frame counter
    hero.updateAnimation();
}

✅ loop: false animations hold on their last frame and set paused = true. Check hero.paused to know when a one-shot animation finishes.
